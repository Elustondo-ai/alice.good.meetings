# SPRINT-005: checks and open items

The service tests go in `poc/poc.test.mjs` (ST5) and the page checks in `poc/browser-protocol.mjs` (PC5); both use the fixtures of [SPRINT-003](03.5.7-s003-print-and-fixtures.md) and none calls OpenAI. They check the [RT5 rules](03.11-sprint-005-response-time-rules.md). SH5-1 is the measurement, which is 04's.

| ID | Check | Rule |
| --- | --- | --- |
| ST5-1 | scripted partial deltas, then the completed event: no reader call before it and exactly one after | RT5-1 |
| ST5-2 | the snapshot given to the reader holds only final items, and a changed final item still gives `corrected-evidence` | RT5-1 |
| ST5-3 | the model schema has no `reply`; a reading without it is accepted; the Question and bullets shown are as before | RT5-2 |
| ST5-4 | two reader inputs of one session share the same package part byte for byte, and the snapshot comes after it | RT5-3 |
| ST5-5 | each reader and answer call writes one `model_call` with every field of RT5-4 and no text | RT5-4, ML-11 |
| ST5-6 | when the fixture gives no usage, the token fields are `null` and nothing fails | RT5-4 |
| ST5-7 | each speech turn with a reader call writes one `question_timing` with the fields and the two differences of RT5-5; with no Focus, `focusVersion`, `questionMs` and the differences are `null` | RT5-5 |
| ST5-8 | a `stop` message with buffered speech sends a final commit and writes its transcript before `session_stopped`, with no reader call, Focus or answer from it | RT5-6 |
| ST5-9 | when the tail does not arrive in 3 seconds, `speech_lost` with `audioMs` is logged and the session ends | RT5-6 |
| ST5-10 | only if built: no reader call without a final item newer than the last snapshot | RT5-7 |
| ST5-11 | after `model_call`, `question_timing` and `speech_lost` are added the header `version` is still 1, and an unknown event type or field does not stop the log being read | RT5-8 |
| PC5-1 | pressing Stop sends `stop` and keeps the socket open; with a service that closes late the Stop button reads "Stopping…" and Start is disabled | RT5-6 |
| PC5-2 | the page closes when the service closes, or after about 4 seconds if it does not, and then shows the Stopped state (SS-8) with Start enabled | RT5-6 |
| SH5-1 | 04's method on the same question list before and after: calls by outcome, tokens and cached tokens, and median and worst `toQuestionMs` and `toBulletsMs` | RT5-4, RT5-5 |

## Open items

- **04:** confirms RT5-4 and RT5-5 cover its fields; it fixes the threshold and the pass rule.
- **05:** the data statements, since the call's content is unchanged, only its order.
- **Q-S5-1 (Pablo, via the lead):** does the page show one line "Last words not captured" when `speech_lost` happens? Default: the log only.
- **09:** whether `phase` can be dropped (RT5-2); where the API reports cached tokens; app.js closes the socket at once on Stop today (lines 537 and 538), which RT5-6 changes.
- **Not covered:** the 0.8 s pause rule, the transcription wait (C6) and the language setting (C7); they are outside this sprint.
- Existing checks that assume partial text or a `reply` may need updating by 09.

## Build order (the lead's)

1. RT5-4 and RT5-5 logging lands first as its own revision, with no change in behaviour (RT5-8).
2. The before-runs are measured on that revision.
3. RT5-1, RT5-2, RT5-3 and RT5-6 each land as their own revision, measured one by one.
