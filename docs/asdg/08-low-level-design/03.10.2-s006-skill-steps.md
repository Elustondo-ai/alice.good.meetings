# Preparation skill: the steps

The seven steps of the process picture, one rule each, in order. It is part of the [specification](03.10-sprint-006-preparation-skill-specification.md). Pablo's aim is to "foresee every reasonable question"; completeness cannot be proved, so the rules below fix a floor that can be checked.

| ID | Rule | Ties to |
| --- | --- | --- |
| KP-1 | **Check.** Inputs present (KI-3), folder ignored (KF-1), `index.md` read if it exists. The run mode is chosen from the input hashes and `answers-from-pablo.md` (KU-1) and said at the start. | |
| KP-2 | **Inventory the job description.** Every requirement (skill, tool, responsibility, qualification, soft skill, nice-to-have) gets an id J-n, the quoted sentence (at most 25 words) and `must` or `nice`. | Pablo 22 Nov |
| KP-3 | **Inventory the résumé.** Every claim (role, project, tool, technology, number, achievement, certificate) gets R-n and where it appears. | Pablo 22 Nov |
| KP-4 | **Read the ChatGPT analysis** for what it stresses, as C-n hints. A hint can start a topic or a gap; it is not evidence (KT-3). | |
| KP-5 | **Group** J, R and C items into topics (for example "AI assistants", "cloud", "languages"). Every J-n and R-n maps to at least one topic. `index.md` holds the coverage table, and any unmapped item is listed with a reason. | |
| KP-6 | **Research on the web** for each topic, the company, the role and the technologies: what the company does, its products and news, how its interviews run, and what is commonly asked about each technology. At most 5 sources per topic, each with its address and the date read. Without web access the step is skipped and the run says "no research this run"; a source that cannot be read is noted as unreadable. Either way the pages work from his documents and no web fact is made up. | KT-5, KV-2 |
| KP-7 | **Write the `me/` pages.** Evidence from his documents and answers (tagged, KT-1); a technical-depth ladder for each technical topic (what it is; how he used it, with the tools, features and versions to recall; trade-offs and failures); the Gaps where the documents are silent. | Pablo 22 Nov (AI tools example) |
| KP-8 | **Write the job topic pages.** At least three likely questions per topic where the kinds fit: typical, technical, behavioural. Each has a prepared answer (first person, at most 150 words, behavioural ones as situation, action, result) and three bullets of at most 120 characters, using only tagged evidence. | TP-4; KT-4 |
| KP-9 | **Pool the questions** into `questions/typical.md`, `technical.md` and `behavioural.md`, each line linking to its topic, and add the generic set (about me, why this company, strengths, weakness, conflict, failure, salary, questions for them). | |
| KP-10 | **Gap list.** Each missing or unverified detail becomes one exact question to Pablo with its topic and why it is likely asked, such as "Which AI assistants did you use, for which tasks, with which features?". At most 15 new gaps per run, those on `must` requirements first. | KT-2 |
| KP-11 | **Proposals.** The ten presets and the digest are written to the job folder, never to `interview/` (KO-1 to KO-4). | |
| KP-12 | **Report.** `runs/<date>.md` holds counts (topics new, changed, retired; gaps; sources; skipped steps) and no résumé text. The chat summary is at most 10 lines. | KV-1 |
| KP-13 | **Too large for one run.** The skill works through topics in order of `must` weight within a size and time limit (Q10). Whatever it did not reach is named in the run report and the chat summary by J-n and R-n with the reason, marked `not processed` in the coverage table, and nothing is cut silently. The next run continues from them, or Pablo splits the package. | UC-10.1 |
