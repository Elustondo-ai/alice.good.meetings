# ASDG continuation pilot observed interactions

Five fresh agent contexts exercised the installed fixture skills on 21 October 2026, with follow-ups retaining local focus.
They inherited the configured model; an exact model identifier was not exposed in the trial receipts.
These were actual tool-assisted agent interactions, not native Codex picker tests or independent human reviews.
Native title controls and writes were unavailable by exercise scope; all fixture files remained unchanged.

| Trial | Observed result |
| --- | --- |
| Unfocused Status on empty client | Reported Focus None, recognized scaffolds and recommended the installed Purpose selector; did not force a complete Context package |
| Purpose selection on empty client | Activated ASDG-02, inspected scaffold evidence and asked who needs help and what should become easier |
| Purpose selection on partial client | Recognized the substantive unregistered draft and asked whether remembering the question or structuring an answer is the first outcome |
| Accepted fixture plus explicit assessment assignment | Assessed the current bundle, qualified simulated acceptance, preserved it and recommended the existing Use Cases selector without switching focus |

| Facts-only Status after selection | Returned factual status without advice, rename, role switch or writes |
| Rejected recommendation | Assessed only audience and non-goals as requested; identified missing non-goals and kept the outcome decision deferred |
| Changed target with unknown identity | Asked for the new project's name or location without attributing the old fixture's state to it |
| Missing stakeholder interview | Actual file read failed; reported the unavailable source and withheld the recommendation rather than inventing stakeholder intent |

## Representative outputs

Empty opening: “Who is this project meant to help, and what should become easier for them?”
Partial opening: “Which should the first improvement help a job seeker do: remember the current question, or structure their answer?”
Dismissal follow-up: “Non-goals are missing. The draft does not say what the product deliberately excludes.” The first-outcome decision remained deferred.
Missing evidence: “The stakeholder's intended priority remains unresolved, so I'm holding the change recommendation.”

## Evidence limits and deviations

The pair legitimately recommended the same outcome decision from different scopes; different perspectives do not require artificially different actions.
Receipts showed one factual status collection per requested operation, with Status's suggestion reusing its result; no recursive Status/Suggestion invocation was reported.
Two trials attempted an unnecessary guessed filename before following the real linked guidance. Both reported the miss and continued without fabricated source claims.
Mandatory contract reads made activation verbose; the source contract does not require displaying all tool receipts in ordinary user replies.
Unknown selector and failed activation recovery remain documented acceptance exercises; they were not newly exercised here.
Missing-file recovery was observed; a live runtime permission denial was not simulated as a successful native check.
