## Decisions by Pablo (the design to build next)

- A clear question is the last thing said before a pause (0.8 s for now, to be fine-tuned).
- The system assumes the pause ends a question and does not wait for Confirm.
- Recovery is to repeat the question clearly and pause again; a later pause replaces the earlier reading. The Confirm and Clear live buttons are not needed in the new flow (remove them, or reduce them to optional).
- Pablo watches the monitor line to see what was heard. No "Report a problem" button is required.
- The agent must interpret the question in the context of the package. Example: Pablo says "CIBC"; the speech recognizer hears "BBC"; the package is about CIBC, so the question must read "CIBC".

## Why "CIBC" can become "BBC" today

`poc/agent.mjs` (the step that reads the question) receives only the transcript, not the package. `poc/answer.mjs` is the only step that receives the package, and it gets the question after it was already misheard. The transcription session has no vocabulary hints.

## Next work, in this order

   - At session start, extract names and acronyms from the package locally (no model call) and pass them to the transcription session as vocabulary hints.
   - Give the question-reading step the package, with the rule: if a word sounds like a name or acronym from the package, use the package's spelling; never add anything that was not said.
   - Add offline tests with the fake transcription and a fixture package (never the private package).
2. **Automatic one-call flow.** After each pause, one model call returns the cleaned question, whether the package covers it, and the answer points and details. If no clear question is found, keep the last good answer and show a small "no question heard" note. Remove the Confirm step; the Focus question is set automatically after the pause.
